# 25：网页登录任务拆分与第一步骨架

本轮是任务布置与骨架示例。助手检查了现有源码，没有创建网页功能文件，没有实现登录，也没有执行本任务的验收。下面由你创建文件、补全实现，完成后再进行源码评审和实际验证。

## 一、先确定要完成的行为

浏览器打开 `/login` → 输入账号密码 → 请求现有登录 API → 保存会话凭证 → 进入 `/app` → 请求 `/api/v1/auth/me` 确认身份 → 显示用户名 → 可以注销。

先把这个闭环做好，再接文件列表、上传与下载。网页登录复用现有 MySQL 认证，不另建用户表、不复制密码校验逻辑、不修改 Qt 协议。

真实接口见 [AuthHttp.hpp](../../src/server/auth/AuthHttp.hpp)：

| 操作 | 请求 | 成功响应 | 前端注意点 |
|---|---|---|---|
| 登录 | `POST /api/v1/auth/login`，JSON `account/password` | 200，包含 `user`、`token`、`expiresAt` | 登录字段是 account，不能写成 username |
| 校验会话 | `GET /api/v1/auth/me` | 200，包含 `user.id/user.username` | 带 `Authorization: Bearer <token>` |
| 注销 | `POST /api/v1/auth/logout` | 200，`{"ok":true}` | 同样携带 Bearer |

登录失败可能返回 400、401、429、503；浏览器 fetch 收到这些状态并不会自动抛异常，要检查 response.ok/status。网络请求失败才通常进入 catch。

## 二、五步任务路线

| 步骤 | 你实现的内容 | 验收结果 |
|---|---|---|
| 1：页面入口 | 公开登录页、固定脚本路由、表单骨架 | `/login` 可访问；匿名 `/upload` 和旧 `/` 仍为 401 |
| 2：提交登录 | auth.js 发 JSON 请求；login.js 管理按钮和提示 | 正确账号获得会话；错误密码保留页面并提示；连续点击不重复请求 |
| 3：登录后页面 | 增加 app.html/app.js，校验 me、显示用户名、注销 | 刷新可恢复校验；失效凭证回登录；注销后旧凭证失效 |
| 4：文件功能接入 | 明确 JSON 文件列表契约，接上传下载 | 每次数据请求带 Bearer，中文文件名可正常往返 |
| 5：异常与回归 | 服务不可达、429、会话过期、注销失败、Qt 回归 | 错误可理解；不把网络失败当密码错误；原 Qt 登录仍可用 |

当前只做第 1 步，建议时间盒 60～90 分钟。后面的步骤这里只列目标，暂不展开实现。

路径约定：`/login` 和后续 `/app` 是公开页面外壳，不包含私有数据；API 与文件数据路由继续认证。暂时保留旧 `/` 的鉴权，浏览器从 `/login` 进入。以后再决定根路径是否重定向。

会话方案预定为复用 Bearer：学习版在本机同源页面使用 sessionStorage 支持刷新恢复；它可被同源 JavaScript 读取，不是 HttpOnly cookie。不要存密码或把 token 放进 URL、日志；面向部署时单独评估 cookie 会话和相应防护。此轮不实现会话保存。

特别注意：浏览器跳转页面、`<a>` 下载、location.reload() 都不会自动带上你保存的 Bearer。旧 index.html 的上传 fetch 也未携带认证头。因此登录成功后直接跳到旧 `/` 不能完成闭环。后续 `/app` 应用脚本发带凭证的请求，文件列表另定 JSON 接口，不把旧 HTML 当列表 API。

只在文件还不存在时使用这些骨架；不要覆盖已有实现。

| 文件 | 职责 |
|---|---|
| WebPages.hpp | 精确匹配公开资源路由、读取固定文件、回复 HTTP |

这些文件应随程序存在，缺失代表服务部署不完整，本任务约定返回 500；错误正文用固定短句，不输出磁盘绝对路径。响应发出后立即结束当前处理路径，不能再次发送 200。

### 2. 在 Service.hpp 接线

加入 `#include "WebPages.hpp"`，并在 GenHandler 中找下面这个位置：

```cpp
auto &self = *static_cast<Service *>(arg);
if (WebPages::handle(req, path)) return; // 新增：严格只处理公开资源白名单
if (auth::AuthHttp::handle(req, path, self.auth_)) return;
// 原 health 分支、authenticate、上传下载和旧根路径逻辑继续保留。
```

为什么放在 authenticate 前面？匿名用户需要先拿到登录页面和脚本，才能发送登录请求。为什么必须严格白名单？不能因为要提供页面，就让 /upload、/download/ 或旧文件列表跳过认证。
