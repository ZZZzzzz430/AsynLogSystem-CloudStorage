## 3. 两条不能混淆的调用链

认证链：

```text
LoginWindow::onLoginClicked()
  → readServerUrl() + 非空检查
  → 保存服务器地址快照 + 设置 loginPending_
  → loginRequested(serverUrl, account, password)
  → ApiClient::login()                  ← E01，当前明确失败
  → loginFinished(verified, message)
  → LoginWindow::handleLoginResult()
  → authenticationSucceeded(serverUrl)  ← 只有 verified=true 才发
  → main 创建 MainWindow / 注入服务器地址 / show
  → LoginWindow::hide()
```

连接测试链：

```text
登录页或主页面的测试按钮
  → ApiClient::testConnection()
  → GET 服务器根路径 /
  → connectionFinished(ok, httpStatus, message)
  → 恢复各自页面的按钮并展示提示
```

这两条链没有“连接成功即登录成功”的接线。登录页测试连接期间禁止同时提交认证，避免两个操作相互覆盖状态。

## 4. 先做哪一个练习

建议先补 **E02：本地文件预检**。它不依赖新服务端认证协议，范围是一份文件和少量函数；不要一次实现全部 TODO。

### E02：补全 `MainWindow::validateSelectedFile(QString &reason) const`

当前函数已经有可编译的签名与失败占位，你只需要替换函数体，不改窗口切换逻辑。

输入是成员 `selectedFilePath_`。`selectedFileSize_` 只是选择时的展示快照，验证时必须重新读文件状态，因为选择后文件可能被删除或修改。

预期行为：

1. 没有选择文件时失败，填写原因。
2. 路径已不存在或不是普通文件时失败。
3. 文件无法打开读取时失败；不要仅因为扩展名正确就通过。
4. 空文件失败，大于 `1024 * 1024` 字节失败；正好 1 MiB 可以通过。
5. 全部检查成功后清空 `reason` 并返回 true。
6. 本函数不发上传请求、不读取整份正文、不在这里操作 UI。

建议思考顺序：`QFileInfo` 获取当前元数据 → 检查文件类型与大小 → 用 `QFile` 验证实际可打开 → 返回结果和原因。函数内临时打开的文件离开作用域就关闭；之后 E04 上传仍要重新打开文件并处理变化，预检不能消除选择到发送之间的竞争。

验收清单：

| 输入/操作 | 预期 |
| --- | --- |
| 13 字节含 NUL 文件 | 预检通过，但当前上传接口仍返回“服务暂不可用”，不能显示上传成功 |
| 空文件 | 拦截，不调用上传接口 |
| 1 MiB 文件 | 允许进入上传接口 |
| 1 MiB + 1 字节文件 | 拦截 |
| 选择后删除/增大文件 | 使用最新状态拦截 |
| 取消重新选择 | 保留原候选，不发网络请求 |

目前已完成选择与展示，**完整 D02 仍待你补齐预检并验收**。

### E01：真实认证

练习入口：`ApiClient::login(serverUrl, account, password)`。

- 先与服务端确定真实地址、方法、字段、响应和失败语义；当前旧服务没有可直接套用的认证契约。
- 使用已有 `manager_` 异步请求，管理 reply、超时和取消；所有最终路径统一收口并释放对象。
- 检查 HTTP 和业务身份结果；HTTP 200 或 JSON 可解析本身不能证明身份有效。
- 只有身份确认通过时才发 `loginFinished(true, ...)`，其余情况发 false 和原因。
- 未来需要增加会话/令牌类型与生命周期，并将同一会话交给主页面的 ApiClient；当前只传服务器地址，不能假设两个 ApiClient 已共享认证。
- 为异步重试加入请求标识，过滤过期结果；当前 `loginPending_` 只适合一个等待中的请求，不能区分旧请求和新请求。

验收：错账号/错密码/服务关闭均停留登录页；真实有效凭据才打开一个主窗口；地址与该次提交一致；关闭主窗口后进程退出。不把占位 false 改成 true 作为业务验收。

### E03：会话偏好、注册与找回

“记住登录状态”和“自动登录”目前禁用，注册/找回只给出明确提示。接入真实会话恢复、过期与注销机制后再启用，不使用明文配置保存密码。自动登录也要检查会话，不以本地勾选状态放行。注册/找回须使用真实后端或正式页面。

### E04：上传

入口：`ApiClient::uploadFile(serverUrl, localPath)`。

依据既有 [接口架构参考](14-Qt与存储服务接口架构参考.md) 和当前 `Service.hpp` 的旧协议完成 low 上传。重点是原始二进制请求体、文件名 UTF-8 Base64 请求头、QFile 活到 reply 完成、非成功 HTTP 与业务失败处理。把真实字节进度转发到 `transferProgress`，等待最终确认后才发 `uploadFinished(true, ...)`。

UI 的 `onUploadClicked()`、进度槽和完成槽已接好。当前 `onTransferProgress()` 收到 100% 只提示等待确认，不提前标记文件已上传。

### E05：下载

入口：`ApiClient::downloadFile(serverUrl, remoteName, targetPath)`。

主页面已采集远端名和保存路径；用户取消保存时不发请求。你负责路径编码、异步读取、临时输出、写入错误/长度/HTTP 状态检查、成功才提交和失败清理。使用 QSaveFile，避免覆盖原目标后才发现下载失败。当前占位不会创建目标文件。

### E06：列表与取消

刷新按钮目前只给出服务不可用提示。先确认真实的文件列表 API，再实现列表、错误态和刷新；不抓 HTML 冒充用户文件 API，也不把本地候选表当作远端文件表。之后补传输取消和关闭清理。若将来允许修改服务器地址，须重新处理该服务器对应的认证会话，不能把旧令牌直接发送给另一个地址。

## 5. 生命周期要点

- LoginWindow 的输入框、卡片、布局、阴影与 ApiClient 都随父对象释放；没有手动重复 delete。
- `ui` 只是主页面控件的访问包装对象，析构时删除包装对象；实际控件和 ApiClient 由 QObject 树释放。
- MainWindow 无 QWidget 父窗口，由 main 中的 unique_ptr 管理；不设置 `WA_DeleteOnClose`，以免重复释放。
- 成功后先显示主窗口，再隐藏登录窗口；不关闭或删除栈上的登录对象。最后一个可见窗口关闭后退出事件循环，随后析构对象。
- 回调指定接收对象/context；都在 GUI 线程使用，没有新增线程或锁。
- 文件表接管 `QTableWidgetItem`；QIcon 管理自己持有的图像，无需外部释放。
- 密码提交后清空输入框、恢复密码显示模式，不写日志；清空输入框不等于安全擦除 QString 内存。
