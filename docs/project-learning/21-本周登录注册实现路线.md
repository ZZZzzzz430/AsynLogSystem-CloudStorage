## 本周交付范围

完成“注册 → 登录 → 查询当前身份 → 注销 → 再次登录”的 Qt 与真实服务闭环；补齐输入校验、重复账号、错误凭据、断网、数据库故障和会话过期处理。

本周暂缓记住登录、自动登录、邮箱/短信验证码、找回密码、修改密码、第三方登录和用户文件隔离。找回密码保留明确的暂不可用提示。登录功能通过不代表多用户云盘已完成。

## 周三：核实基线，固定规则

任务要求：

1. 核对服务实际使用的数据库、users/sessions 表结构、用户名唯一约束及业务账号权限，不重复初始化或覆盖现有数据。
2. 用真实测试账号验证已有登录、me、logout；区分数据库连通与用户认证成功。
3. 固定本周规则：仅用户名登录，区分大小写；新注册用户名建议限 3～32 位 ASCII 字母、数字、下划线；新密码至少 12 字节、最多 128 字节，禁止静默截断或去除密码首尾空格。已有账号登录规则保持兼容。
4. 注册仅填写用户名、密码、确认密码；邮箱本周不采集。确认密码由 Qt 校验，不传给服务端。
5. 固定注册契约：POST /api/v1/auth/register，接收 username/password；成功返回 201 和公开用户信息，参数错误 400、用户名冲突 409、限流 429、服务不可用 503。注册成功后返回登录页并回填用户名，不自动创建会话。

验收要求：正确密码成功；错误密码、不存在用户失败且提示一致；无 token 的 me 被拒绝；注销后原 token 失效。记录实际结果及阻塞项。

涉及范围：[数据库迁移](../../src/server/database/migrations/001_auth.sql)、[数据库说明](../../src/server/database/README.md)、[认证服务](../../src/server/auth/AuthService.cpp)。

## 周四：完成服务端注册

任务要求：

1. 沿用 HTTP → AuthService → UserRepository 分层，不在 HTTP 处理器直接拼接 SQL。
2. 服务端独立检查 JSON 类型、必填字段、用户名格式、密码长度及请求体大小，不能依赖客户端校验。
3. 复用已有安全随机用户 ID 和 scrypt 密码哈希；数据库只保存哈希，不返回 password_hash。
4. 将现有仓储 insert 纳入正式注册流程；使用预处理语句，依靠数据库唯一约束处理重复账号及并发竞争。
5. 通过独立迁移/授权操作给业务账号增加所需的 users INSERT 权限；保持原有最小权限，不使用 root 运行服务。同步本地初始化说明，已有环境也要能升级。
6. 正确区分用户名冲突和数据库故障；数据库失败不得返回注册成功，也不得留下不完整用户。
7. 注册与登录增加有界的频率限制，超过限制返回 429；不能为每个任意输入无限保存限流记录。
8. 日志记录操作类型、结果和耗时，不记录密码、完整 token 或数据库凭据。

验收要求：新账号仅新增一条用户记录且无会话；相同用户名并发注册仅一个成功，其余冲突；异常 JSON、超长输入和数据库不可用均返回约定错误，服务不崩溃；限流可触发并在约定时间恢复。

涉及范围：[AuthHttp](../../src/server/auth/AuthHttp.hpp)、[AuthService](../../src/server/auth/AuthService.hpp)、[用户仓储](../../src/server/database/UserRepository.hpp)、[密码工具](../../src/server/auth/Crypto.hpp)。

## 周五：完成 Qt 注册与登录交互

任务要求：

1. 注册按钮打开注册页面或对话框，提供用户名、密码、确认密码和返回登录入口。
2. Qt 负责即时提示和确认密码检查；网络请求统一通过 ApiClient 异步执行。
3. 提交期间禁用重复提交；成功、失败、超时后恢复控件状态；关闭窗口后异步结果不得访问已销毁对象。
4. 分别展示输入错误、账号重复、请求过多、网络失败和服务不可用；不要把所有失败都显示为密码错误。
5. 注册成功返回登录页并回填用户名，清除密码输入；注册失败保留必要输入供修正。
6. 只有服务端确认登录成功才进入主窗口；测试连接成功不能代替登录成功。
7. 为认证请求设置明确超时，网络等待期间窗口仍可操作。

验收要求：无需数据库工具创建业务用户，单靠 Qt 就能注册并登录；密码不一致不提交；连续点击不产生重复请求；断网、超时后能够重试。

涉及范围：[登录窗口](../../Client/loginwindow.cpp)、[ApiClient](../../Client/ApiClient.cpp)、[窗口启动流程](../../Client/main.cpp)。

## 周六：补齐会话生命周期

任务要求：

1. me 成功时显示当前用户名；401 清除本地身份并返回可操作的登录页，避免停留在失效主窗口或直接退出整个客户端。
2. 所有需要认证的请求采用一致的 401 处理；503 与网络错误不得误判成 token 失效。
3. 注销成功后清除 token、关闭主窗口并返回登录页；网络失败显示未确认并支持重试，不宣称服务端已注销。
4. 保持现有 8 小时会话策略；客户端重启需要重新登录，服务端重启后未过期 token 应继续有效。
5. 测试新旧请求交错返回，确保注销后迟到的响应不会恢复旧身份，也不会覆盖新账号状态。
6. 验证 token 只向登录服务的同源地址发送；更换服务器地址后不得沿用旧身份。

验收要求：过期、无效、已注销 token 均被拒绝；有效 token 在服务端重启后可用；注销后能立即切换账号登录；数据库故障和断网不会把用户错误地标为凭据无效。
