## 3. 源码检查发现，计划里必须补上的缺口

### 3.1 登录缺的不只是一个 HTTP 请求

真实链路应为：

```text
Qt 提交账号密码
  → 服务端登录路由
  → AuthService
  → UserRepository 查询用户
  → 验证密码哈希
  → SessionRepository 持久化会话摘要和到期时间
  → 返回公开身份、原始 token 和到期时间
  → Qt 保存会话并传给主页面的网络层
```

当前还没有 `SessionRepository`；`AuthService` 也只保存用户仓储引用。因此 DB05 需要新增会话仓储并调整依赖，不能只填 `AuthService::login()` 的函数体。

另外，[main.cpp](../../Client/main.cpp) 目前只传服务器地址；[loginwindow.cpp](../../Client/loginwindow.cpp) 和 [mainwindow.cpp](../../Client/mainwindow.cpp) 分别创建 ApiClient。登录对象里保存 token，不会让文件页对象自动获得 token。必须安排明确的会话传递。

### 3.2 数据库库目标没有接进真实服务

[database/CMakeLists.txt](../../src/server/database/CMakeLists.txt) 只生成独立库和 SDK probe；[Makefile](../../src/server/Makefile) 的 `test/gdb_test` 仍只编译原来的 Test.cpp、base64.cpp。DB06 要把实际依赖接进 Linux 服务目标，不能只运行 SDK probe 就宣布接线完成。

Windows Qt + Windows MySQL SDK 骨架，与 Linux/libevent 服务是不同构建环境。先确定实际服务运行在哪里，以及服务进程能访问哪一个开发库；不要默认 Linux 进程的 `127.0.0.1` 就是 Windows 的 MySQL。

### 3.3 接真实传输前，要补最小错误链

以下是源码检查结果，尚未在本轮做故障复现：

| 位置 | 当前问题 | 需要达到的结果 |
| --- | --- | --- |
| [FileUtil::SetContent](../../src/server/Util.hpp) | write 失败分支未返回 false，后面仍可能返回 true | 写入/结束写入失败不能报成功 |
| [DataManager::Storage](../../src/server/DataManager.hpp) | SetContent 失败只记日志，仍返回 true | 持久化错误向上传播 |

### 08 开始前，先冻结最小认证契约

沿用 14 的草案作为起点，在实施 08 时保存成正式契约，确认后两端都按同一份实现：

- `POST /api/v1/auth/login`；先只支持用户名，JSON 字段为 `username`、`password`。Qt 参数叫 account 不影响协议映射；页面“账号/邮箱”提示也应改成实际支持的“用户名”。
- 成功：200，包含 `data.user`、`data.token`、`data.expires_at`；失败使用统一错误结构。不存在用户与错密码统一为凭据错误，数据库故障另报服务不可用。
- token 在客户端首版只存内存，绑定本次服务器 origin；后续受保护请求携带 Bearer。登录响应不能包含 passwordHash 或数据库配置。
- 会话仓储除创建外，还需安排“按摘要查找有效会话”和“撤销会话”；13 的文件鉴权与 15 的退出都依赖它。
- 账号规则、口令长度、正文大小、超时及过期时间要写清楚；不要一端发 account，另一端只读 username。

这只是待落实的约定，不表示路由已经存在。08 先完成服务端并用 HTTP 验证，再做 09，避免客户端错误和服务端错误混在一起。

### 13 太大，按四个小交付连续做

1. 建立文件记录与独立存储位置：file_id、owner_id、显示名、storage_key、大小、状态、创建时间；不自动迁移 `storage.data`。
2. 增加受保护的 v1 上传：先校验会话，限制输入，写入与记录失败时有明确状态/清理规则。
3. 增加只查本人记录的列表和按 ID 下载；未知文件及他人文件返回约定的不可见结果；验证 A/B 同名不同内容。
4. 切换到认证运行模式，关闭或隔离旧匿名入口；确认旧 `/`、`/upload`、`/download/` 和静态路径不能读取新数据。过渡 legacy 实验结束后再做此切换。

### 15～70 分钟：自己补预检

- [ ] 路径为空：失败，给原因。
- [ ] 当前路径不存在或不是普通文件：失败。
- [ ] 读取当前文件大小，0 字节拒绝，超过 `1024 * 1024` 拒绝，正好 1 MiB 接受。
- [ ] 使用 QFile 尝试只读打开，实际打不开则失败；文件对象离开作用域自动关闭。
- [ ] 成功清空 reason 并返回 true；失败返回 false 且 reason 非空。
- [ ] 函数内不发请求、不读整份文件、不改 UI；成员中的旧大小只用于展示。

提示仅限：当前已有 QFileInfo 包含；使用 QFile 时补直接头文件依赖。优先局部变量和提前返回，不增加工作线程、数据库依赖或新的窗口层。预检通过后文件仍可能变化，11 上传时还要处理重新打开/读取失败。

### 70～105 分钟：编译与边界验收

先用现有 Qt6 Kit 重新构建正式 Client。构建配置沿用 17，不重新搭 CMake。

| 场景 | 预期 |
| --- | --- |
| 未选择文件 | 函数失败；正式 UI 中上传按钮原本就不允许进入 |
| 13 字节含 NUL 的文件 | 预检通过；现阶段上传占位仍返回失败，不显示已上传 |
