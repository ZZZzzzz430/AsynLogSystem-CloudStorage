## 12. 动手验证前：准备、构建和启动

以下是当前 Windows 机器可用的 PowerShell 命令。不要把它们直接粘贴到 Linux shell。数据库不需要启动。

### 12.1 准备环境

```powershell
Set-Location 'E:\QtProjects\AsynLogSystem-CloudStorage'
$env:PATH = 'E:\Qt\6.8.3\mingw_64\bin;E:\Qt\Tools\mingw1310_64\bin;' + $env:PATH
```

PATH 让程序找到 Qt 和编译器运行库。更换电脑需替换实际安装路径。

### 12.2 第一次配置构建目录

```powershell
& 'E:/Qt/Tools/CMake_64/bin/cmake.exe' -S Client -B build/client-registration -G Ninja -DCMAKE_MAKE_PROGRAM=E:/Qt/Tools/Ninja/ninja.exe -DCMAKE_CXX_COMPILER=E:/Qt/Tools/mingw1310_64/bin/g++.exe -DCMAKE_PREFIX_PATH=E:/Qt/6.8.3/mingw_64 -DBUILD_TESTING=ON
if ($LASTEXITCODE -ne 0) { throw '配置失败，请先检查输出。' }
```

### 12.3 编译

```powershell
& 'E:/Qt/Tools/CMake_64/bin/cmake.exe' --build build/client-registration --parallel 4
if ($LASTEXITCODE -ne 0) { throw '编译失败，不要继续用旧程序判断新代码。' }
```

每次修改 C++ 后都要重新编译。Qt Creator 中则选已安装的 Qt 6.8.3 MinGW Kit，构建 Client 项目；测试入口仍可使用终端运行。

### 12.4 启动客户端做输入校验练习

```powershell
& ./build/client-registration/Client.exe
```

不开服务器仍可以完成第 2、3、4 节的本地练习。合法提交后出现连接失败是正常的，但应恢复按钮。

## 13. 不需要数据库的自动化验证

### 13.1 一次运行全部

```powershell
& 'E:/Qt/Tools/CMake_64/bin/ctest.exe' --test-dir build/client-registration --output-on-failure
Get-Content -Encoding UTF8 ./build/client-registration/registration-tests.txt
```

CTest 只显示 1 个测试目标；内部 Qt Test 报告有 20 项通过，其中包含初始化和清理。不要把它说成 20 个完全独立的业务场景。

退出码 0 表示测试通过。测试脚本可能在 GUI 程序环境下不直接向终端输出细节，因此以指定报告文件为准。

当前 Windows offscreen 测试可能打印字体目录或 propagateSizeHints 的 QWARN。先看报告末尾的 failed 数和退出码；这些已观察到的平台提示不是业务断言失败。不要把其他未知警告也一概忽略。

### 13.2 只运行一个场景，边看边学

先执行第 12.1 节环境设置。在构建目录运行，报告和预览都会留在构建目录：

```powershell
Push-Location ./build/client-registration
try {
    & ./client_registration_tests.exe clientValidationMakesNoRequests -platform offscreen -o exercise-validation.txt,txt
    Get-Content -Encoding UTF8 ./exercise-validation.txt
} finally {
    Pop-Location
}
```

替换中间的函数名即可选择不同练习。`offscreen` 表示无需显示桌面窗口也能运行真实 Qt 控件；它没有跳过网络类，测试仍会通过本机 TCP 收发 HTTP。

| 测试函数名 | 先看什么代码 | 通过说明什么 |
|---|---|---|
| clientValidationMakesNoRequests | validationError、submit | 密码不一致/格式错误时请求数为零 |
| registrationWireContractAndDuplicateGuard | ApiClient::registerUser | 连续调用只发一次、JSON 正确、不自动创建客户端会话 |
| errorMessages | authenticationFailure、结果槽 | 8 组响应显示对应错误，并恢复输入 |
| timeoutRestoresControlsAndCanRetry | timeoutReply、setPending | 超时后可重试、输入保留、定时事件仍运行 |
| networkFailureCanRetry | 错误分类、请求状态恢复 | 连接拒绝后恢复服务可重试 |
| registrationReturnsToLoginThenAuthenticates | 回填槽、登录门禁 | 注册不进入主窗口，之后登录才进入 |
| healthAndMalformedLoginNeverAuthenticate | 登录响应校验 | 连接成功、缺 token、错误密码都不能认证 |
| loginTimeoutAndServiceErrorsRecover | 登录改动 | 登录超时、429、503 后恢复并可再登录 |
| closingRegistrationDiscardsLateResult | done、cancelAuthentication | 旧注册回复不影响新表单 |
| closingAndDestroyingLoginDiscardsLateResult | LoginWindow::reject | 关闭或销毁登录页后不迟到认证 |

### 13.3 选一条错误数据单独观察

```powershell
Push-Location ./build/client-registration
try {
    & ./client_registration_tests.exe 'errorMessages:duplicate' -platform offscreen -o exercise-conflict.txt,txt
    Get-Content -Encoding UTF8 ./exercise-conflict.txt
} finally {
    Pop-Location
}
```

`duplicate` 是 errorMessages_data 中那一行测试数据的名字，对应 409。它不需要先在数据库创建同名用户，因为是模拟服务直接给出这类响应。

### 13.4 测试文件里先认识三个东西

```cpp
QSignalSpy result(&client, &ApiClient::registrationFinished);
QTRY_COMPARE(result.count(), 1);
QCOMPARE(peer.requests.size(), 1);
```

- QSignalSpy：记录信号发了几次和参数，像一个观察记录器。
- QTRY_COMPARE：允许事件循环继续处理，等异步条件满足再检查。
- QCOMPARE：立即比较已知结果。

不要在刚 post 后马上用普通 QCOMPARE 要求回复已经到达；异步操作需要等待。

HttpPeer 是测试用小服务器。`responses` 是预先安排的回复；`requests` 记录实际收到的请求。负数 delayMs 表示故意不回复，正数表示稍后回复，用来稳定验证超时和迟到结果。

测试用 120 ms 超时是为了快速检查；生产默认仍是 10 秒。QTimer heartbeat 在等待中还能触发，说明测试覆盖的网络等待没有堵住 GUI 事件循环。

## 17. 真实服务联调：与模拟测试分开记录

本地表单练习、编译、模拟 HTTP 测试都不需要 MySQL。真正“仅靠 Qt 注册并登录”需要已启动的 MySQL、可运行的 HTTP 服务、对应业务账号 INSERT 权限。

2026-11-13 检查时，SessionRepository.hpp 仍有结构体结尾分号缺失、Dbstatus 大小写不一致等既有阻塞。完整服务还涉及第 22 份文档列出的会话接口问题。本手册不修改这些服务端代码，也不把模拟测试通过写成真实入库通过。

准备就绪后，按以下顺序验证，优先使用隔离测试环境：

| 编号 | 操作 | 预期 | 证据 |
|---|---|---|---|
| R1 | Qt 填实际服务器根地址，点测试连接 | 显示可达，仍停留登录页 | 界面状态 |
| R2 | 用 Qt 注册新的合法用户名 | 返回登录页并回填用户名，密码为空 | 界面状态、服务端 201 日志 |
| R3 | 输入该用户密码登录 | 进入主窗口 | 登录成功结果 |
| R4 | 再注册同名账号 | 显示账号重复，允许修改 | 409 日志与提示 |
| R5 | 密码不一致时点击注册 | 本地拒绝，无注册请求 | 本地提示、请求计数或断点 |
| R6 | 同一请求等待期间连续点击 | 一次请求 | 精确请求计数或服务端对应日志 |
| R7 | 服务不可达后恢复，再重试 | 失败后控件恢复，之后可提交 | 两次操作结果 |
| R8 | 等待中关闭窗口 | 不崩溃、不误回填、不意外打开主窗口 | 界面与日志；模拟测试可稳定复现 |

用户名使用 4～16 位允许字符，例如 `learn_001`。连续提交前注意服务端注册为进程共享每窗口 5 次，之前失败也会消耗额度；遇到 429 先等窗口恢复，避免把限流当作其他用例失败。

真实服务超时不必通过破坏数据库或停公共服务制造；优先使用本机模拟不回应的用例。自动化中存在“能恢复”的断言，比只观察一次失败更完整。
